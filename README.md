# LegitBuilder

LegitBuilder собирает загрузочный JAR из Fabric-мода. Результат содержит payload DLL, carrier DLL, манифест с SHA-256 и Java-загрузчик. Откройте JAR при запущенном Minecraft: он найдёт единственный процесс нужной версии, проверит вложенные файлы и запустит загрузку. Если подходящих процессов несколько, укажите PID явно.

Проект рассчитан на позднюю загрузку в уже работающую JVM. Это влияет на Mixin, access widener и одноразовые события запуска игры. Перед сборкой своего мода прочитайте [контракт мода](docs/MOD_CONTRACT.md).

## Сборка

Нужны Windows x64, JDK 21, Python 3, CMake и MSVC C++ Build Tools. Зависимости Mixin/ASM/Fabric Loader и JNA закреплены хешами и лежат в репозитории. Подробности и настройка путей — в [инструкции по сборке](docs/BUILD.md).

```powershell
.\build.ps1 -Jar C:\path\to\your-mod.jar
```

Итоговый файл: `LegitBuilder.jar` в корне проекта; копия остаётся в `build/release`. Для запуска откройте его двойным щелчком или выполните:

```powershell
java -jar .\LegitBuilder.jar
```

Загрузчик выбирает процесс по версии Minecraft из манифеста исходного мода. При неоднозначности используйте `java -jar .\LegitBuilder.jar --pid 12345`. Журнал загрузки записывается в `%USERPROFILE%\.legitbuilder\logs`.

## Устройство

- `jar-to-dll/` читает Fabric JAR, извлекает классы, ресурсы, Mixin-конфиги, refmap, access widener и entrypoints, затем генерирует исходник payload DLL.
- `runtime/` содержит Java-мост к нативному загрузчику, поддержку Mixin и работу с уже загруженными классами.
- `carrier/` создаёт PE-образ для отображения в целевой процесс.
- `injector/` проверяет хеши, отображает образ и запускает `ManualMain`.
- `build.ps1` выполняет эти этапы по порядку и собирает один JAR.
- `tests/` содержит проверки JVMTI, Mixin и адаптации классов.

Последовательность и границы ответственности описаны в [архитектуре](docs/ARCHITECTURE.md). Репозиторий не содержит исследовательские дампы, старые готовые сборки и исходный JAR мода. Сборка всегда получает мод через `-Jar`.
