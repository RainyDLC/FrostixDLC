# LegitBuilder

LegitBuilder собирает загрузочный JAR из готового Fabric-мода и подключает его к уже работающему Minecraft на Windows x64. Во время сборки классы и ресурсы входного JAR превращаются в payload DLL. При запуске JAR проверяет встроенные DLL, находит один процесс нужной версии игры и запускает payload через `ManualMain`. Исходный мод не устанавливается в папку `mods`, поэтому его поздняя инициализация требует отдельной проверки.

```powershell
.\build.ps1 -Jar C:\mods\my-client.jar
.\scripts\test.ps1 -Jar C:\mods\my-client.jar
java -jar .\LegitBuilder.jar --inspect
```

Готовый файл лежит в корне проекта и в `build/release/LegitBuilder.jar`. Двойной щелчок запускает автоматический выбор процесса, если `.jar` связан с Java. При нескольких подходящих клиентах укажите `--pid` явно. Автоматический запуск пишет журнал в `%USERPROFILE%\.legitbuilder\logs`; журнал payload ведётся отдельно внутри целевого процесса.

Начните с [подготовки мода](docs/MOD_CONTRACT.md), затем прочитайте [правила Mixin](docs/MIXINS.md) и [упаковку ресурсов и шрифтов](docs/EMBEDDED_RESOURCES.md). [Схема инжекта](docs/INJECTION.md) объясняет, что делает загрузчик и где искать отказ. [Сборка и проверки](docs/BUILD.md) перечисляет входы, инструменты и команды. Краткая [карта компонентов](docs/ARCHITECTURE.md) связывает эти документы с исходниками.

Репозиторий содержит загрузчик, генератор, тесты и закреплённые зависимости сборки. Он не содержит исходный JAR мода: каждый результат собирается из файла, переданного через `-Jar`. Успешная сборка и `--inspect` подтверждают упаковку и целостность PE; поведение мода подтверждается только проверкой в соответствующей версии игры.
