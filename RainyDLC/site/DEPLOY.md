# RainyDLC — деплой сайта

Пошаговая инструкция: база → хостинг → админка → домен. Всё бесплатное.

---

## 1. База данных — Supabase (бесплатно)

Бесплатный тариф: **500 МБ PostgreSQL**, встроенная система аккаунтов (Auth),
500 тыс. MAU. Для сайта-визитки с аккаунтами — с запасом.

1. Зарегистрируйся на [supabase.com](https://supabase.com) → **New project**
   (имя `rainydlc`, регион ближайший — `EU West`, пароль для БД придумай и сохрани).
2. Дождись создания (~2 мин) → слева **SQL Editor** → **New query**.
3. Вставь целиком файл `supabase/schema.sql` из этого проекта → **Run**.
   Это создаст таблицы `profiles`, `site_settings`, RLS-политики и триггер автосоздания профиля.
4. **Project Settings → API**: скопируй:
   - `Project URL` → `NEXT_PUBLIC_SUPABASE_URL`
   - `anon public` key → `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `service_role` key → `SUPABASE_SERVICE_ROLE_KEY` (⚠️ никому не показывай)
5. **Authentication → Sign In / Up**: включи **Confirm email** (защита от фейковых ящиков).
   В **Auth → Rate Limits** оставь включёнными лимиты — это защита от перебора паролей.

### Вариант B: через Supabase CLI (удобно для Antigravity)

Создание проекта — только в браузере (2 мин, шаг 1 выше). Дальше всё в терминале:

```bash
supabase login                          # откроет браузер — один клик
supabase link --project-ref xxxxx       # ref — из URL дашборда, спросит пароль БД
supabase db push                        # применит миграцию из supabase/migrations/
```

Ключи для Vercel всё равно берутся из дашборда: **Project Settings → API**.

## 2. Хостинг — Vercel (бесплатно)

Бесплатный тариф: **100 ГБ трафика/мес**, автодеплой из GitHub, HTTPS из коробки,
глобальный CDN. Для Next.js — лучший вариант.

1. Залей проект на GitHub (репозиторий может быть приватным).
2. [vercel.com](https://vercel.com) → **Add New → Project** → выбери репозиторий → **Deploy**.
3. После деплоя: **Settings → Environment Variables** → добавь три переменные из шага 1:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `SUPABASE_SERVICE_ROLE_KEY` ← без префикса `NEXT_PUBLIC`, иначе ключ утечёт в браузер!
4. **Redeploy**, чтобы переменные применились.

> Альтернатива с безлимитным трафиком — **Cloudflare Pages** (тоже бесплатно).
> Но Vercel проще для Next.js: деплой в 3 клика.

## 3. Админка (только ты)

1. Открой сайт → **Войти → Регистрация** → зарегистрируй свой аккаунт, подтверди email.
2. В Supabase → **SQL Editor** → выполни:
   ```sql
   update public.profiles set is_admin = true where email = 'твой@email.com';
   ```
3. Открой `твой-домен/admin` — увидишь панель: **список пользователей** (бан/разбан/удаление),
   **переключатель техработ**, статистику.
   - Не-админ на `/admin` видит обычный 404 — самого факта существования панели не раскрываем.
   - Себя забанить/удалить нельзя (защита от случайного клика).

**Техработы двумя способами:**
- Через админку (переключатель пишет флаг в БД, срабатывает мгновенно, без редеплоя).
- Через хостинг: в Vercel → Environment Variables добавь `SITE_MAINTENANCE=true` → Redeploy.
  Переменная окружения перекрывает флаг из БД — аварийный рубильник.

## 4. Домен

| Вариант | Цена | Комментарий |
|---|---|---|
| `rainydlc.vercel.app` | **0 ₽** | Даётся сразу при деплое, HTTPS включён |
| `eu.org` | **0 ₽** | Бесплатный, но одобрение заявки — недели |
| `rainydlc.fun` / `.xyz` | **~100–200 ₽/год** | Дёшево первый год, дальше ~1000 ₽/год |
| Любой домен у Cloudflare Registrar | по себестоимости | Без наценок, продление дешевле всех |

Подключение своего домена: Vercel → **Settings → Domains** → **Add** → прописать
NS/A-записи у регистратора как покажет Vercel. HTTPS выпустится сам.

## 5. Что закрыто по безопасности

Честно: **сайта, который «невозможно взломать никак», не существует** — это тебе скажет
любой инженер. Но закрыто всё, что реально закрывается:

- **Пароли** — хранит Supabase Auth (bcrypt), мы их не видим и не храним вообще.
- **Сервисный ключ БД** — только на сервере (`SUPABASE_SERVICE_ROLE_KEY` без `NEXT_PUBLIC`),
  в браузер не утекает никогда.
- **RLS-политики** — пользователь читает/правит только свой профиль; `is_admin`
  поднять через сайт нельзя (политика + триггер), только SQL в дашборде.
- **Админка** — проверка `is_admin` сервисным ключом на сервере; API-роуты валидируют
  вход (UUID-формат, типы) и требуют админа; 403/404 вместо подробных ошибок.
- **Перебор** — rate-limit 60 зап/мин на `/api/*` + встроенные лимиты Supabase Auth;
  сообщения об ошибках входа общие (не раскрывают, существует ли email).
- **Боты** — honeypot-ловушка в форме регистрации, подтверждение email.
- **Заголовки** — HSTS, CSP, `X-Frame-Options: DENY` (защита от кликджекинга),
  `nosniff`, `Referrer-Policy`, `Permissions-Policy`, скрыт `X-Powered-By`.
- **XSS** — React экранирует вывод, `dangerouslySetInnerHTML` не используется нигде.
- **CSRF** — сессии Supabase в httpOnly-куках с SameSite.

```bash
cp .env.example .env   # и заполни ключами из шага 1

```
