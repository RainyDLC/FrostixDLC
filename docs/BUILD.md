# Сборка и проверка

Рабочая среда: Windows x64, JDK 21, Python 3, CMake и Visual Studio C++ Build Tools. По умолчанию `build.ps1` использует генератор `Visual Studio 18 2026`; при другой версии задайте `-Generator`. Путь к CMake можно передать через `-CMake`. Путь к JDK задаётся через `-Jdk` или `JAVA_HOME`.

```powershell
.\build.ps1 -Jar C:\mods\example.jar -Jdk 'C:\Program Files\Java\jdk-21'
```

`scripts/build_runtime.ps1` компилирует Java-мост против закреплённых Mixin, ASM и Fabric Loader из `dependencies/compile`. Хеши этих файлов и JNA проверяются по `dependencies/lock.json`. Эти библиотеки нужны для сборки; они не подменяют библиотеки работающего клиента. Поэтому перед проверкой в игре используйте ту же версию Fabric/Mixin, под которую рассчитан исходный мод.

Сборка выполняет пять этапов: компиляция генератора; компиляция runtime-классов; генерация и компиляция payload DLL; генерация carrier по `SizeOfImage` payload; запись хешей в `loader-abi.json` и упаковка JAR. Все промежуточные файлы лежат в `build/`. В итоговый JAR входят `mod-payload.dll`, `vcruntime_aux_carrier.dll`, `loader-abi.json`, Java-классы инжектора и JNA. Если в корне проекта есть `offline-assets/`, её содержимое тоже включается.

Полная проверка пересобирает JAR и запускает Java, Mixin и JVMTI-регрессии:

```powershell
.\scripts\test.ps1 -Jar C:\mods\example.jar
```

Нативные тесты запускаются в отдельных JVM и проверяют capture, redefine, повторный поиск загруженного класса и восстановление таблицы при завершении VM. Тест ресурсов сравнивает классы входного JAR с байтами в сгенерированном payload. Это не заменяет проверки конкретного мода в игре. Перед выпуском проверьте меню, одиночный мир, внешний сервер, переход между мирами и перезагрузку ресурсов. Ошибки `RedefineClasses` или отсутствующие ресурсы требуют исправления исходного мода; замена проверки на принудительное продолжение не исправляет состояние JVM.

Файл `LegitBuilder.jar` открывается двойным щелчком, если `.jar` связан с Java. Без аргументов выбирается только один подходящий процесс нужной версии. Командный режим `--pid` оставлен для нескольких одновременно запущенных клиентов и диагностики.
