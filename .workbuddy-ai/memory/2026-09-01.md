## Target Hud: добавил режимы и статы (HP + зачарованное золотое яблоко)

Файлы:
- `src/client/java/ru/white/utils/other/UseCooldowns.java` — добавил `COUNTERS` карту и `count(uuid, Item)` для подсчёта сколько раз цель съела чарку за сессию. `clear()` тоже чистит COUNTERS. Инкремент в `trigger()`.
- `src/client/java/ru/white/module/impl/display/InterFace.java` — добавил `targetHudMode` ModeSetting (Полный/Классический/Компактный), плюс `onWorldLoad` → `UseCooldowns.clear()` и тик `UseCooldowns.tick` в `onUpdate` (чтобы детект работал без Use Tracker).
- `src/client/java/ru/white/module/impl/display/interfaceimpl/TargetHud.java` — W_BASE=148, правая панель с сердцем (`hud/heart/full`) и яблоком (`Items.ENCHANTED_GOLDEN_APPLE`) через `DrawContext.drawGuiTexture`/`drawItem`. `drawFace` параметризован размером. Новый метод `renderCompact` для режима «Компактный» (100×22, голова+имя+HP/чарка справа).

Важно: в блоке пересчёта размеров внутри onRender (строка ~117) W_BASE надо держать = 148, не 114 — иначе ширина в режиме «Полный» будет 114. Один раз уже попался на этом.

Иконки:
- Сердце: `Identifier.ofVanilla("hud/heart/full")` + `drawGuiTexture`
- Яблоко: `ctx.drawItem(stack, -8, -8)` + `scaleFix = 2F / mc.getWindow().getScaleFactor()` (паттерн из ClickHelper)

Окружение: gradle в этой машине заблокирован stale-локом `~/.gradle/caches/journal-1/journal-1.lock` (IDE держит), и loom-джары в кеше пустые (0 классов). Полный compile проверить не получилось, только ручной ревью.

Найденные причины (проверено по байткоду ClientPlayerInteractionManager 1.21.11, obf-имя класса `hio`):
1. `clientPlayerInteractionManager.clickSlot()` сначала делает `ScreenHandler.internalOnSlotClick(...)`
   (клиентский предикт), потом шлёт `ClickSlotC2SPacket` с ревизией. Если сервер отклоняет —
   прилетает `SetPlayerInventoryS2CPacket` и клиент откатывается. Старый код проверял только
   предикт и молча считал свап успешным.
2. Свап был заперт за `!mc.player.isSprinting()`, а спринт глушился через `Sprint.get().tick += 1`
   (срабатывает только на СЛЕДУЮЩЕМ тике) — гонка, из-за которой клик часто вообще не отправлялся.
3. Порог здоровья без гистерезиса: `health <= threshold` дёргался каждый тик на границе значения.
4. `setKey(false)` вызывался без гарантированного `setKey(true)` — клавиши движения «залипали».
5. `resetSwapBack()` на таймауте стирал `oldSlot`, старый предмет оставался в слоте тотема.

Что сделано:
- Конечный автомат `Goal.{NONE,TOTEM,RETURN}` + подтверждение: после клика ждём ответ сервера
  (`EventPacket` на `InventoryS2CPacket`/`ScreenHandlerSlotUpdateS2CPacket`/`SetPlayerInventoryS2CPacket`)
  либо таймаут, потом ПРОВЕРЯЕМ реальный оффхенд и при неудаче повторяем, но не чаще RETRY_MS=120 мс,
  максимум N попыток, затем COOLDOWN_MS=1000 мс.
- Спринт глушится прямо в `sendSwap()` (`setSprinting(false)` + `Sprint.tick += 2`), клик уходит в том же тике — гонки нет.
- Гистерезис порога (защёлка `active`).
- `releaseKeys()/restoreKeys()` — всегда симметрично, плюс сброс в `onDisable`/`onEnable`/смерти.
- Клик только если `currentScreenHandler == playerScreenHandler` (защита от сундуков), syncId берётся
  из `currentScreenHandler` (иначе клик дропается с warn "Ignoring click in mismatching container").
- Возврат предмета: `returnSlot` = индекс инвентаря 0..35 + сверка `areItemsAndComponentsEqual`.
- Новые настройки: «Проверять свап», «Задержка проверки» (150 мс), «Попыток» (3), «Гистерезис» (1.0), «Уведомления».

Проверка: `./gradlew compileClientJava --offline` — успешно (только существующие unchecked warning в ModuleManager).

## Конфликт слияния в AutoTotem (дополнение)

Пользователь запустил `.\gradlew runClient` → 44 ошибки `illegal start of type` и т.п.
Причина: в проекте был **незавершённый interactive rebase** (`pick 9139f3a` onto `a3a72f3`),
файл AutoTotem.java содержал маркеры `<<<<<<< HEAD` / `=======` / `>>>>>>> 9139f3a`.
HEAD-сторона = старый модуль (`oldSlot`, `canSwap()`, `if(!checkToAttack()) swap();`),
сторона 9139f3a = новая версия. Маркеры НЕ были в файле во время моей первой компиляции —
пользователь делал git-операции после неё.

Разрешено в пользу новой версии, файл перезаписан целиком (Write), `git add` + `git rebase --continue`.
Итог: `main` = 93e358f, чисто, ahead of origin/main на 1 коммит.
`./gradlew compileClientJava --offline` → BUILD SUCCESSFUL.

Урок: перед/после правки исходников проверять `git status` на наличие rebase/merge в процессе,
и грепать маркеры `^(<<<<<<<|=======|>>>>>>>)` по src/, если компилятор выдаёт «illegal start of type»
на строках, которых вроде бы нет.
